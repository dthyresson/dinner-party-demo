# Expected outputs

Published deliverables, generated by the agents, not pre-filled. **One owner per file** — no role
writes another's.

| File | Owner | Schema |
| --- | --- | --- |
| `menu.md` | Chef | Courses (starter/main/dessert) with serves and notes; allergens and substitutions; portion assumptions; revision notes |
| `shopping-list.md` | Shopper (Procurement) | Requested quantities; on-hand deductions with who confirmed; priced lines with unit price, line total and stock; totals and stock flags |
| `schedule.md` | Scheduler | Arrivals with basis; timeline with an owner per activity; conflicts and the decision each needs |
| `budget.json` | Finance | `food_total`, `non_food_total`, `total`, `total_cap`, `food_cap`, `status`, `notes`, `line_items[]`; `total = food_total + non_food_total`, `total <= total_cap`, `food_total <= food_cap` |
| `decisions.md` | Planner | Approved; proposed; pending host approval; changes since last revision — each line naming its owner |
| `invitations/<guest>.md` | Guest Manager | `status: draft`, `to`, `subject`, body — never sent |

Artifacts describe the *current plan* and carry revision/date notes after a disruption. They are
deliberately absent until a run writes them; an empty stub would look like a finished deliverable.

A correction to someone else's artifact is a message to its owner; the owner republishes.
